# teerex v0.1.0-alpha.1

An experimental Apple-silicon Mac CLI for explicit Rex observation, offline comparison, bounded change/status-report waiting, and local run-and-collect. This release ships the selected Phase 3 #1/#3/#8 implementation, not the entire Rex phase or a cartridge manager.

## Download and verify

The [GitHub prerelease](https://github.com/jcbbge/teerex/releases/tag/v0.1.0-alpha.1) provides `teerex-v0.1.0-alpha.1-aarch64-macos.tar.gz` and `SHA256SUMS`. Download both into a new directory. On macOS, from that directory:

```sh
shasum -a 256 -c SHA256SUMS
tar -xzf teerex-v0.1.0-alpha.1-aarch64-macos.tar.gz
./teerex --help
```

The archive contains only `teerex`, `README.md` (this guide), and `RIGHTS.md`. Its executable is **300712 bytes**, SHA-256 `c39108dc3bfedf240c62c4f7b0c683f6f06b5ef59fa78cd377aa8b38b007abe9`. Checksums detect changed downloads; they are not independent publisher authentication. The executable has no Developer ID signature or Apple notarization. Browser-downloaded quarantine/Gatekeeper behavior has not been validated; do not disable system-wide protections to use this alpha. Building reviewed source is another option.

Nothing is installed globally, added to `PATH`, registered as a service, or written into Rex configuration. Invoke the extracted executable directly. To upgrade, extract a reviewed release into another directory and validate it before deliberately replacing your previous copy. To remove it, stop its foreground invocation and remove only the extracted files you own; teerex creates no persistent hooks or automatic history. Explicitly run programs can have their own side effects and are not automatically uninstalled.

## Compatibility and use

Live commands were validated on **arm64 macOS 27.2**, separately installed **Rex 0.1.0-preview.16**, API **13**, server commit `aa2db1b21261b479a550559fb70e2c3a66c07ba2`. Other macOS/Rex versions and Joshua's M5 installation are unverified. API revisions other than 13 fail closed. No Linux/VPS, Intel Mac, remote execution or graphical-plugin support is promised. Rex is proprietary, separately obtained, and not bundled. No teerex license has been selected; see the included `RIGHTS.md` or the [tagged rights record](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.1/RIGHTS.md).

Have the compatible `rex` executable on `PATH` and an already-running server. Deliberately select its absolute Unix socket and full terminal IDs; teerex does not discover a target from focus or environment hints. In these examples, replace placeholders with your known local server and target:

```sh
./teerex observe --socket /absolute/path/to/rex.sock \
  --session session:FULL-UUID --block block:FULL-UUID --max-bytes 4096

./teerex compare --before /private/path/before.json --after /private/path/after.json

./teerex watch --socket /absolute/path/to/rex.sock \
  --session session:FULL-UUID --block block:FULL-UUID \
  --baseline /private/path/before.json --timeout-ms 5000 \
  --status-state done

./teerex run --socket /absolute/path/to/rex.sock --cwd /absolute/working/directory \
  --timeout-ms 10000 --max-bytes 4096 -- /bin/pwd
```

Before `compare` or `watch`, deliberately save successful observations privately and check their exit status. Observation text, paths, identifiers, reports and diagnostics can contain secrets; output is escaped, **not redacted**. There is no automatic capture/history file. A partial terminal capture is a **screen-and-scrollback prefix**, not a guaranteed latest viewport. Metadata reads are non-atomic and report freshness stays unknown.

A status match requires changed evidence for the selected record relative to the original baseline. An identical retained `done` does not match again. A new `done` report does not establish process exit, task completion, freshness or permission. `run` executes argv on the CLI machine, **not** in the observed terminal or on the socket's server. It is not a sandbox; arbitrary commands inherit the account's authority. Cleanup covers the owned process group, not detached/re-grouped descendants or a crash/SIGKILL of teerex itself.

See the complete [observation/comparison/wait contract](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.1/items/observe/README.md) and [execution contract](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.1/items/run/README.md) for JSON schemas, bounds, exit statuses, provenance and unknowns. No live-input guard, Rex-wide input lease, human clutch, installer or background service is included.

## Validation and source

The exact executable passed **38 public-CLI checks** (27 observation/comparison/wait and 11 execution) in three consecutive disposable-Mac runs and a final repeat. Native and Mac builds, Zig formatting, seven native offline comparison checks and 120 differential comparison cases also passed. Integration fixtures use private disposable sockets/configurations, not Joshua's Mac or VPS. No hosted CI workflow exists in this release; these are executed local/disposable-Mac checks, not a hosted-CI claim.

Measured same-target short observation median improved **76.271 → 18.288 ms**; five-second quiet wait child-CPU median **1877.955 → 96.748 ms**, excluding the Rex server. These are controlled disposable-Mac samples, not M5, peak-memory, whole-system energy or productivity guarantees. Full methods and controls are preserved in the item contracts.

Source is tagged [v0.1.0-alpha.1](https://github.com/jcbbge/teerex/tree/v0.1.0-alpha.1). Rebuild with Zig **0.15.2** from the repository root:

```sh
zig build -Doptimize=ReleaseSmall -Dtarget=aarch64-macos --prefix zig-out/mac
```

The definitive PDF-only phase/scoring review, historical research, and unassigned non-Rex H01–H08 remain preserved. Shipping this CLI does not convert deferred or unsupported historical suggestions into approved features.

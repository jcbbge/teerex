# teerex v0.1.0-alpha.5

**An inspectable operating-layer increment, not completion of the entire alpha.5 brief.** Visible terminal surfaces and native palette registration, foreground inbox/fleet boards, address-bound seat routing, typed decisions, managed protocol/profile launches and responsibility, structural recovery/manual update inventory, and explicit named-host fleet installation are built into teerex. No Rex fork, plugin daemon or hidden agent fallback is introduced. [Remaining gates](#not-delivered) are release scope, not promises implied by the version number.

Confirm this exact tag and checksummed assets on the [prerelease page](https://github.com/jcbbge/teerex/releases/tag/v0.1.0-alpha.5) before installation. A source build identifying itself as alpha.5 is not a published release. Alpha.1–4 tags/assets and the historical Phase 1–3 roadmap remain unchanged. The [new product contract](../alpha5.md) supersedes earlier exclusions without rewriting history.

## Who / What / When / Where / Why / How

- **Who:** Joshua and explicitly authorized human/setup/worker agents. Installation alone grants no permission to act on a pane or host.
- **What:** real public-API commands with private, inspectable state and bounded receipts separating requests, attempts, acknowledgements, readback and unknown outcomes.
- **When:** invoked explicitly. Boards refresh only as foreground visible terminal programs; no unobservable background fleet service is installed.
- **Where:** Apple-silicon macOS or Linux x86_64 command hosts, each selected through a private named-host config or explicit socket. `m5`, `hive`, `m1` are ordinary configured names, not hardcoded endpoints.
- **Why:** answer what was launched, who is responsible, what was reported/observed, and what remains unknown without silently typing over the operator or recreating uncertain work.
- **How:** install exact verified bytes, inspect help/host plans, then use the item guides below with explicit full addresses. File paths belong to the selected command host; they are never silently copied there.

## Assets and prerequisites

Five archives plus external `SHA256SUMS` preserve the existing installer format:

- `teerex-v0.1.0-alpha.5-aarch64-macos.tar.gz` and `teerex-v0.1.0-alpha.5-x86_64-linux.tar.gz`: three flat regular files, `teerex`, this guide as `README.md`, and `RIGHTS.md`.
- `teerex-v0.1.0-alpha.5-cartridges-aarch64-macos.tar.gz` and `teerex-v0.1.0-alpha.5-cartridges-x86_64-linux.tar.gz`: independently built existing experimental native payloads (ten Mac/seven Linux), not combined-CLI wrappers. New operating-layer composition is in the combined CLI; surfaces/boards/agents/recovery are **not** advertised as independently packaged cartridges in this increment.
- `teerex-v0.1.0-alpha.5-onboarding.tar.gz`: source-relative operator/agent guides, migrations and reviewed lifecycle tools. No Rex binary, private endpoints, state, captures or credentials.

The combined executable is built with Zig0.15.2 ReleaseSmall. Linux uses static musl; Mac linker ad-hoc signing is not Developer ID signing/notarization or Gatekeeper certification. Python3.9+ stdlib is required for named targets, boards, agents, recovery, fleet install and managed palette installation. Legacy native direct-socket tools retain their existing dependency boundary. SSH additionally needs explicitly provisioned identity and pinned known-host trust. Target fleet hosts need Python3.9+, Bash and normal installer tools. Rex is acquired separately; no redistribution rights are inferred.

Check only the asset selected for your platform, extract into a new directory, then run `./teerex --version` and `./teerex --help`. Expected version is exactly `teerex 0.1.0-alpha.5`. Obtain `SHA256SUMS` from this exact release; a hash detects byte changes, not independent publisher authentication.

From reviewed source/onboarding, use explicit `install` or `upgrade`, not both:

```sh
bash tools/install/teerex-install install --version v0.1.0-alpha.5 --prefix "$HOME/.local/opt/teerex-managed"
bash tools/install/teerex-install inspect --prefix "$HOME/.local/opt/teerex-managed"
bash tools/install/teerex-install verify --prefix "$HOME/.local/opt/teerex-managed" --version v0.1.0-alpha.5
```

Use `upgrade` instead when that managed root is already active. Core installation never adopts/deletes a manual folder or changes PATH, shell profiles, Rex configuration or running programs. `inspect`/`verify` do not execute candidate binaries and report busy/stale-lock state conservatively. [Installer fields and recovery](../install.md); [fleet consent and PATH limits](../fleet-install.md).

## Verification

The combined source was compiled and executed on disposable Debian13 x86_64 and Apple-silicon macOS26.3.1 with checksum-pinned Rex preview.16/API13 (`aa2db1b21261b479a550559fb70e2c3a66c07ba2`). Public suites include observe29, send10, spawn7, jobs14, surfaces15, boards12 (including its native stdin-route helper), agents12 with both combined gates, recovery11, adapters11, maneuvers21, filter9, cache12, targets7 and native child4. Mac additionally runs run11, doctor9 applicable checks and offstage7. Core installer20 and fleet11 pass on both hosts; historical public installer controls remain alpha.1 controls, not alpha.5 download proof.

Actual loopback OpenSSH acceptance tests use temporary generated credentials only. Strict pinned-key install/upgrade/retained rollback, native SHA/version, known_hosts with spaces, username/HOME/hostname checks, unknown/changed-key refusal and named-root observe/boards probes are exercised. Root targets7 additionally installs **its exact native executable bytes**, invokes the installed `--version`, and replans fleet installation from outside the source checkout using embedded support files. Fleet helper fixtures are not silently presented as alpha.5 release binaries.

Surface tests run on actual Mac API10/12/13 and Linux API13; older Mac APIs also exercise update inventory and snapshot refusal. API11 is not actual-build certified. [CI](../ci.md) records selected lanes and exact-head status must be checked separately. Cross-compilation is not Mac runtime acceptance. Synthetic terminal HTML captures were rendered and inspected for empty/open/narrow/resolved boards and tiled/float/tab/move content; they are **not Rex.app placement/palette-click evidence**.

The distinct report-session regression was reproduced before the fix: Lua returned a stream-not-attached conflict. Spawn now attaches that explicitly supplied report session before inspecting its terminal; the regression and managed notifications pass without changing the report session's layout. Cancellation tests cover inherited ignored INT and bounded cleanup of the owned native client's actual resistant transport without closing agents or stopping the server. Lost creation/brief/move/reload/restore evidence never authorizes automatic retry.

- Exact issue #10 topology certification, API11/every old build/OS, Rex.app graphical painting and real paid Claude/Codex/pi hook certification.

These are explicit unfinished requirements of the larger brief. Alpha.5 ships useful tested slices while retaining the unfinished work, earlier release history, private data and host-level safety blockers.

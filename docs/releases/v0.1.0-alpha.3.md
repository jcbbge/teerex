# teerex v0.1.0-alpha.3

**Combined experimental Rex CLI for Apple-silicon macOS and Linux x86_64.** This release adds native Linux observation/watch supervision, visible agent `spawn`, whole-message `send`, Mac compatibility `doctor`, bounded Mac `offstage`, offline `maneuver-check` and evidence `filter`, plus a reviewed source-tree installer and pinned CI. It preserves alpha.2's API10–13 compatibility without updating/restarting Rex or closing existing panes. Not every original proposal is implemented: strong guarded input and the human/agent clutch still lack a verified host enforcement boundary.

## Command coverage

| Command | Platform and accepted revision contract | What success actually means |
| --- | --- | --- |
| `observe`, `watch` | macOS/Linux, integer API10–13 | Bounded attributed evidence/change or selected status-report difference; not completion, freshness, atomic snapshot or permission. |
| `compare`, `filter` | Offline, schema1/API10–13 packets with exact matching target/source | Explicit evidence comparison; filter omits only identical intermediate payloads and keeps every comparison plus the latest full checkpoint. No cosmetic classifier or persistent cache. |
| `spawn` | macOS/Linux, integer API10–13 | One acknowledged new terminal window, requested without focus change, with verified attachment and agent-core metadata. Not startup/readiness/completion or an input lease. |
| `send` | macOS/Linux, integer API10–13 | One FROM-envelope paste and Enter event acknowledged separately. Not atomic application delivery, consumption or prompt safety. |
| `run` | Mac-only, integer API10–13 | Real local argv exit/output/deadline/cancellation evidence. Executes on the CLI host, not the selected server; not an agent launcher or sandbox. |
| `doctor` | Runtime Mac-only, integer API10–13 and overlapping CLI/server support | Selected advertised observe/watch/run requirements and identity drift; `behavior_certified=false` always. Does not assess spawn/send/offstage or permission. |
| `offstage` | Mac/API13-only | One invocation-owned off-layout terminal's exit/capture and verified close/absence. Not agent launching, isolation, a durable registry or descendant-proof cleanup. |
| `maneuver-check` | Offline, explicitly API13 definitions/packets | A manually authored recognizable-start check against saved evidence. No learning, transition replay, guarded input or approval. |

## Existing-server workflow

Use a deliberately selected trusted Rex on PATH and an already-authorized, existing absolute socket/session/block. No autostart, restart, update or pane closure is an installation/compatibility prerequisite. The [alpha.2 existing-server read-only smoke procedure](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/docs/releases/v0.1.0-alpha.2.md#check-an-existing-server-without-restarting-it) still applies. Save any captures deliberately with private permissions; stdout can contain unredacted terminal text, paths and secrets.

Agents/workers/sidecars on Joshua's machines must be visible Rex/teerex terminals, including Rivet. `spawn` is the launcher, not `run` or `offstage`. Use exact addresses, not guessed labels/focus. After setting the existing target values:

```sh
./teerex spawn --socket "$SOCKET" --session "$SESSION" --name worker \
  --cwd /absolute/workspace --report-to-session "$PARENT_SESSION" \
  --report-to-block "$PARENT_BLOCK" -- /absolute/path/to/agent --its-arguments
```

It exports the new pane's AGENT_SESSION/PANE, LC_REX_SESSION/BLOCK, AGENT_NAME/LC_AGENT_NAME and explicit AGENT_REPORT_TO/LC_AGENT_REPORT_TO through fixed positional-parameter shell code. It does not configure agent-core, SSH forwarding, alerts, Rivet or machine guards. A missing cwd fails closed before executing the requested program. Creation can succeed even if the program later fails; inspect its retained visible terminal. **Lost creation evidence is uncertain, not safe to retry.** No automatic close/retry guesses which resource to adopt.

Whole-message sending targets an existing dedicated agent terminal:

```sh
./teerex send --socket "$SOCKET" --session "$SESSION" --block "$BLOCK" \
  --from worker --message-file /absolute/path/to/private-message.txt
```

The regular UTF-8 file becomes `FROM worker: ...`, pasted once, then Enter once on one connection. No draft clearing, chunking, fallback, retry or inbox forwarding occurs. Local inbox markers refuse; the shared same-host/TMPDIR `agent-send` mkdir lock coordinates cooperating senders only. Full raw64KiB input may exceed the smaller encoded-RPC budget and correctly refuse before paste. A paste ACK followed by failed/lost Enter remains uncertain; inspect before resending. Direct clients/human input can bypass the lock, and already-existing drafts are not protected.

See the complete [spawn](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/items/spawn/README.md), [send](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/items/send/README.md), [observe](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/items/observe/README.md), [run](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/items/run/README.md), [doctor](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/items/doctor/README.md), [offstage](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/items/offstage/README.md), [maneuver](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/items/maneuvers/README.md) and [filter](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.3/items/filter/README.md) contracts for bounds, exit codes, lifecycle and provenance. Success in one command never authorizes another.

## Safety blockers and delivery boundaries

A separate real API13 probe demonstrated that another client can write while a client holds native block ownership; an invented conditional-observation argument was ignored while input was consumed. Ownership/size preference is **not an exclusive input lease**. Therefore guarded live-input `verify_then_write`, immediate human revocation, queued-input invalidation and safe learned-macro replay are not exposed under false guarantees. The maneuver utility checks saved starts only. Offstage has no sandbox and can leak resistant/detached descendants after close or owner crash; no whole-tree guarantee is claimed.

Independent add/remove cartridges, an all-items package, graphical renderer/plugin integration, generic generated clients, automatic C14 presentation, semantic/cosmetic filtering, persistent perception caches, non-Rex runtime/replay work and personal-machine setup remain outside this delivery. Historical planning/research/non-Rex material is preserved. The setup agent separately owns machine/Rivet guards; publication authorizes none of their restarts or configuration changes.

# teerex v0.1.0-alpha.2

**Compatibility-only Apple-silicon Mac release:** observe, compare, watch and run accept integer Rex API revisions **10–13**, preserve the revision actually returned, and name an out-of-range revision when refusing it. This removes alpha.1's API13-only blocker without requiring a Rex update, restart, configuration change or pane closure. It does not include the parallel doctor, installer, Linux, spawn, send, offstage, maneuver or filter work.

## Download and verify

Download `teerex-v0.1.0-alpha.2-aarch64-macos.tar.gz` and `SHA256SUMS` from the [GitHub prerelease](https://github.com/jcbbge/teerex/releases/tag/v0.1.0-alpha.2) into a new private directory, then:

```sh
shasum -a 256 -c SHA256SUMS
tar -xzf teerex-v0.1.0-alpha.2-aarch64-macos.tar.gz
./teerex --help
```

The archive contains only `teerex`, this guide as `README.md`, and `RIGHTS.md`; never Rex or personal captures. The executable is **300888 bytes**, SHA-256 `551243190d91d529fd551a39c38c3b1fbfb62cc6f4dd90b44baff83ab7ced8af`. Checksums are integrity checks, not independent publisher authentication. No Developer ID signature or notarization is supplied, and browser-quarantine/Gatekeeper acceptance is unverified. Do not disable system security to run it. Nothing is installed globally, added to PATH, or written into shell/Rex configuration; replacing your old extracted executable is a deliberate choice. Retain alpha.1 separately for rollback, not as a reason to restart Rex.

## Accepted revisions are not identical behavior

The five observation reads and their existing size/type/provenance checks remain unchanged. Missing/unsupported methods or malformed output still fail rather than becoming empty successful evidence. Reported cwd/status freshness remains unknown and serial reads remain non-atomic. Compare/watch still require the exact source identity: a baseline from API10 cannot silently compare against API12 after a server change. `run` also requires the consumed Lua exec binding; acceptance of a revision does not certify its subprocess, callback, signal or timeout semantics.

Joshua's setup agent supplied an actual successful five-read `collect.lua` run on the existing M5/API10 server after removing the old pin. That is supplied machine evidence, **not an execution performed by this release thread**, and does not prove `run` on that build. The agent reports that current Rex Beta app build1925 contains preview.14/API12; preview.16/API13 CLI availability is not an app-update prerequisite. Updating a server can close its panes and is neither required nor authorized for this compatibility check.

The exact release candidate passed **39 public CLI checks per build** on disposable arm64 **macOS27.2**, against actual **API10, API12 and API13** builds: 28 observe/compare/watch and 11 run checks each. Every build includes real exec callbacks, literal argv/cwd/EOF, binary output, zero/nonzero/signalled exits, deadlines, cancellation and owned-group cleanup, not just advertised shapes.

## Check an existing server without restarting it

Run from an existing visible Rex pane, with this executable, your trusted Rex CLI on PATH, and the known existing absolute socket/full IDs. Do **not** run `server run`, `Update Server`, a restart, or any command closing panes. Set `SOCKET`, `SESSION` and `BLOCK` from the setup agent's already established connection, not guessed focus/labels; substitute their exact values below.

```sh
umask 077
TEEREX=/absolute/path/to/new/teerex
SOCKET=/absolute/path/to/existing/rex.sock
SESSION=session:FULL-UUID
BLOCK=block:FULL-UUID
CHECK_DIR=$(mktemp -d)
rex --autostart=false --server "unix://$SOCKET" api call server.version > "$CHECK_DIR/version.json"
"$TEEREX" observe --socket "$SOCKET" --session "$SESSION" --block "$BLOCK" \
  --max-bytes 600 --timeout-ms 5000 > "$CHECK_DIR/observation.json"
"$TEEREX" compare --before "$CHECK_DIR/observation.json" --after "$CHECK_DIR/observation.json" > "$CHECK_DIR/comparison.json"
```

Each command must exit0. Inspect the observation for exact selected target, source revision equal to direct `version.json`, bounded capture, process, reported-directory and status evidence, `atomic_snapshot=false` and unknown freshness. An empty directory/status report is valid unavailable/report evidence, not a failure or proof of idle. Keep these files private; report the version/build, exit codes, byte counts and whether each node decoded, not raw terminal text or secrets. No program is started or stopped by these three checks.

`run` is an existing separate local-exec interface, **not an agent launcher or a Rex tab**, and inherits account authority. If the setup agent deliberately validates its exec binding from a visible pane, this bounded probe runs only the system printf utility, not an agent/worker:

```sh
"$TEEREX" run --socket "$SOCKET" --cwd "$PWD" --timeout-ms 2000 --max-bytes 256 \
  -- /usr/bin/printf '%s\n' teerex-compat-exec > "$CHECK_DIR/run.json"
```

Require exit0, `exit_report.code=0`, exact UTF-8 stdout `teerex-compat-exec\n`, and the actual source revision; absence/failure is not compatibility proof. The program executes on the CLI machine, not the socket's host. This one smoke probe does not replace process/timeout/cancellation tests. All actual agents, workers, sidecars and messages on Joshua's M5/hive must remain routed through Rex and teerex; this release does not implement the forthcoming visible `spawn` or message `send`, and must not be used to start hidden agent workers.

# teerex v0.1.0-alpha.4

**Five experimental follow-ons, delivered together without changing alpha.3:** independent native cartridges, explicit durable jobs and presentation, five narrow read adapters with local receipts, opt-in historical observation caching, and saved-evidence maneuver libraries. This is not completion of every historical proposal. Strong guarded input and immediate Rex-wide human revocation remain unsupported.

A source checkout or candidate build is not a release. Confirm this exact tag and its assets on the [prerelease page](https://github.com/jcbbge/teerex/releases/tag/v0.1.0-alpha.4) before installation. Alpha.3 stays pinned to commit `8b2827860029e30a3ad5724d357655de155520d5`; neither its tag nor its three-file assets are replaced. Alpha.4 uses explicit version selection, not a rolling latest installer.

Download the selected archive and external `SHA256SUMS` into a new private directory. The release separates:

Every archive is externally checksummed. Catalog manifests separately pin their payload bytes and record build source identity. ## Exact command and compatibility surface

All features remain experimental. API acceptance is not certification of every build. Tested immutable Rex builds are preview.13/API10, preview.14/API12 and preview.16/API13; API11 is numeric-only acceptance. Preview numbers are not API revisions. M5/hive and mixed CLI/server pairs are not certified.

| Surface | Platform / API | Contract |
| --- | --- | --- |
| `observe`, `watch`; offline `compare`, `filter` | Mac/Linux; observation schema1, API10–13 | Existing bounded evidence, explicit target/source, non-atomic reads and unknown freshness remain unchanged. Filter retains comparisons and latest checkpoint; no semantic classifier. |
| `spawn`, `send` | Mac/Linux; API10–13 | Visible worker creation or whole-message paste/Enter transport. Creation is not readiness; ACK is not consumption. Lost ACK never justifies automatic retry. |
| `run`, `doctor` | Runtime Mac; API10–13 | Explicit local argv execution, or advertised selected contract checks. Doctor never certifies behavior, authorization or other commands. Linux runtime unavailable. |
| `offstage` | Mac/API13 only | Bounded invocation-owned off-layout command, not a hidden agent launcher, sandbox or durable registry. |
| `jobs track`, `list`, `inspect`, `adopt`, `present`, `forget` | Mac/Linux; API13 only | Explicit absolute private registry and exact socket/session/block. Local responsibility/monotonic generations, manual review dates and uncertainty receipts; no native ownership takeover or process enforcement. |
| `adapters generate`, `call` | Mac/Linux; integer API10–13 | Five fixed read-only tools derived from validated selected descriptors. Explicit identity/target-bound caller allowlist and revalidation; unauthenticated local receipts, not host enforcement/consent/audit history. |
| `filter cache put`, `get`, `purge` | Offline Mac/Linux; schema1/API10–13 | Explicit private directory, sample and sensitive-storage consent; exact expected observation and source/capture domain. Hits always historical/unverified, with no permission. |
| `maneuver-check --definition FILE …` | Offline Mac/Linux; API13 | Existing single manual saved-start check. No input replay or fresh-state guard. |
| `maneuver-check --library FILE --list`; `--library FILE --observation FILE [--before FILE] --socket ABS --session session:UUID --block block:UUID` | Offline Mac/Linux; API13 | Bounded manual definition library, unique/mismatch/unknown/ambiguous evidence and declared endpoint relations. No chronology, executed transition or authority inferred. |
| `python3 tools/cartridges/cartridges.py` | Mac arm64 / Linux x86_64; Python3.9+ | Independent local lifecycle; no Rex required just to install/list. Payload-specific API/platform restrictions still apply at invocation. |

Use each command's `--help` and feature README for all mandatory flags; do not infer a valid command by joining table labels. Combined `teerex` commands retain their leading verb. Standalone `teerex-jobs`, `teerex-adapters`, `teerex-filter`, etc. omit that verb; `teerex-observe` retains `observe`, `compare`, or `watch`.

## Explicit install, upgrade, rollback and removal

From reviewed tagged source or extracted onboarding:

```sh
bash tools/install/teerex-install install --version v0.1.0-alpha.4
# If a managed version is already active, use upgrade instead:
bash tools/install/teerex-install upgrade --version v0.1.0-alpha.4
bash tools/install/teerex-install list
"$HOME/.local/opt/teerex/current/teerex" --help
# Explicit retained version selection; never an automatic rollback:
bash tools/install/teerex-install rollback --version v0.1.0-alpha.3
```

Choose install OR upgrade as appropriate, not both sequentially. The installer does not change PATH, profiles, Rex configuration, agent launchers, servers or services. It has no cartridge lock/refcount protocol. Removing the active core requires `remove --version v0.1.0-alpha.4 --deactivate` and leaves no active core; it does not stop existing programs.

For cartridges, checksum and extract the matching catalog to a new canonical absolute directory. The Python manager lives in source/onboarding, not inside the core's three-file archive:

```sh
python3 tools/cartridges/cartridges.py install filter --catalog /canonical/catalog --allow-experimental
python3 tools/cartridges/cartridges.py install filter --catalog /canonical/catalog --allow-experimental --apply
python3 tools/cartridges/cartridges.py list
python3 tools/cartridges/cartridges.py run filter -- --help
```

Plans show exact IDs/versions/dependencies/destinations/permissions before explicit `--apply`. To compose all experiments, replace `filter` with `--all` and retain `--allow-experimental`; default ready-only `--all` selects zero current packages. All use the same per-item paths and remain independently removable. Code is versioned separately from retained mutable data. Exact dependency conflicts/cycles and active dependents refuse; invocation leases are cooperative only. `remove ID --version 0.1.0-alpha.4 --deactivate --apply` retires one code version, never data. `restore ID --version 0.1.0-alpha.4 --apply` restores inactive; `activate` is a separate deliberate selection. No purge, forced removal, detached-process guarantee or automatic crash repair exists. See `docs/cartridges.md` for full contract.

## State migration and live-agent boundaries

No automatic alpha.3 state migration is needed or performed. New state is caller-selected: jobs registry, plaintext observation cache, manually authored maneuver library, adapter bundle/local policy/argument files, and cartridge code/data roots. Do not import a worker's scratch fixture or silently adopt a pane. Do not place cartridge data inside the core installer's managed tree. An old alpha.3 executable cannot read these commands; rolling back code does not undo data or cancel jobs.

Keep state/captures private and review exact target/source fields. Cache put requires `--allow-sensitive-storage`; default TTL60s, allowed1–3600s, entry at most1MiB plus at most1MiB pending bytes per selected directory. TTL is checked on access, not an unattended deletion service; reads do not extend it. Purge unlinks data/pending but is not secure erase, encryption, ACL/snapshot control or same-account isolation.

Jobs adoption needs previous owner, current generation, reason and a new manual review deadline on the same live instance/server-host/block-host. Presentation additionally requires exact anchor and explicit focus yes/no; hidden agents/native-owned blocks refuse. Saved uncertain presentation intent prevents automatic retry after lost ACK or a crash. Forgetting metadata is not closing a block. A review deadline never kills a process.

Existing authorized Rex must not be restarted, updated or reconfigured as a prerequisite. All actual agents/workers/sidecars, including Rivet, stay visible through the setup-approved Rex/teerex route. `spawn` is the launcher; `run` and `offstage` are not hidden-agent exceptions. Touch only explicitly designated targets; other tabs are live agents. Installation does not authorize invocation, migration, input, network access or personal-machine changes. Follow `docs/concierge/setup.md` and the existing-server procedure in the alpha.2 guide, using private caller-supplied values rather than a published endpoint.

## Verification and unsupported guarantees

The combined candidate was built natively for static Linux and cross-built for Apple silicon, then actually exercised on disposable Linux and arm64 macOS27.2 with pinned Rex preview.16/API13. Existing observation28, filter9, send9, spawn6, Mac run11/doctor9/offstage7, plus cache12, maneuver21, jobs13 and adapter11 checks passed. Core installer lifecycle/public controls passed on both hosts; four direct child regressions passed on Linux. Native catalog acceptance additionally passed14 manager lifecycle tests and51 managed installed-payload offline checks on each host. Direct installed-payload runtime suites passed109 Linux/136 Mac checks (plus one inapplicable doctor guard skipped on Mac), with real native help/cross-dispatch refusal and per-payload retirement/data retention/inactive restore. Runtime uses direct installed paths to preserve deliberate HOME changes and concurrent senders; this bypasses manager leases. Managed starts have a separate short nonblocking HOME-bound registry contract and can refuse concurrent starts before exec; no managed concurrent-start success is inferred. [CI documentation](https://github.com/jcbbge/teerex/blob/v0.1.0-alpha.4/docs/ci.md) records exact supported lanes and reproduction commands; hosted success must be checked for the final exact pushed head, never inferred from an earlier green commit.

The hosted Mac SDK failure is repaired on public `e16302c`: all four configured checks succeeded after per-job Xcode26.1.1 selection, with tests retained. New follow-on commits still need their own exact-head status. Source/catalog provenance distinguishes the feature candidate from documentation-only follow-up commits; later source edits invalidate earlier binary coverage unless the relevant source is shown identical or rerun.

No host-enforced input lease, atomic verify-then-write, immediate human clutch/revocation, authenticated audit log, sandbox, encryption/redaction, whole-descendant cleanup, unattended cache expiry, semantic classifier, automatic learned replay, generic arbitrary RPC generator, graphical Rex renderer/plugin contract, minimum OS/kernel, API11 actual-build, M5/hive, browser Gatekeeper or productivity guarantee is provided. Historical research and deferred non-Rex work remain preserved. Rex is proprietary and acquired separately; no project license has been selected beyond `RIGHTS.md`.

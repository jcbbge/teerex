# Cross-host waiting navigation

`teerex waiting list|next|back|put-away [--config /ABS/hosts.json] [--hosts hive,m5] [--focus]`

The default config is `~/.config/teerex/hosts.json`; omitted `--hosts` scans **every** configured host. Transport uses the existing explicit named-host configuration, including its SSH identity and known-host checks. Each host is queried through one foreground Rex Lua connection, with autostart disabled. Placed and detached terminals participate. For each pane, the most urgent OSC 7501 record wins: blocked, error, done; equal urgency sorts oldest first, preserving nanoseconds. Working and idle records do not qualify. A failed host is reported in `sources`, sets `complete:false`, exits 1 and prevents focus; missing evidence never becomes zero waiting.

`list` returns unvisited waiting panes without moving focus. `next --focus` focuses the first pane on its owning server, bringing a detached pane into the right third beside that session's active pane first. Without `--focus`, `next` previews the winner without marking it visited. Focus changes server layout state; it does not establish that an app switched hosts or sessions. No client action is guessed or queued. `back --focus` returns to the previous supplied context, including across hosts. Visited timestamps and the return trail live in `~/.local/state/teerex-waiting/navigation.json`; `--state /ABS` selects isolated state. A lock serializes overlapping presses. Only a successfully focused winner is marked visited; a new status timestamp qualifies again. The host name forms part of every visited key.

Supply `--here-host NAME --here-session session:UUID --here-block block:UUID` for exclusion and return navigation. `--here-server LABEL` resolves a Rex action's context label against configured names, host ids and SSH addresses. An unfamiliar label is resolved by finding the exact live session/block across all hosts; missing or ambiguous ownership is an error, never permission to act on the local host. `put-away` requires this exact context and detaches its pane on that host, refusing `seat` and a tab's last placed pane.

`--circuit` selects the triage circuit instead of urgency navigation. It reads live agent launch records and each agent's declared scratchpad `Waiting:` line plus open board decisions from the owning host. Ready live agents repeat in launch-time order across hosts (host and block break ties); `back` walks that order backwards. Status changes do not reorder the circuit. Each arrival temporarily labels the tab with scratchpad Now, Waiting, and the oldest open decision with its prepared default, if present. Moving on restores the previous tab label. Display failures are reported as `display_error` without preventing the walk. The circuit cursor is independent of urgency visited state.

Rexconfig's `next_waiting` delegates cmd+j here; triage j/k adds `--circuit`. `put_away` delegates triage d. A missing teerex executable alone permits the prior local Lua implementation. A present executable with a missing verb, bad configuration or failed host reports failure. The Lua remains in the rexconfig repository; it is not installed by teerex.

Test: `TEEREX_BIN=/ABS/teerex REX_BIN=/ABS/rex python3 items/waiting/test_waiting.py -v`. Set `WAITING_LUA=/ABS/rexconfig/rex/waiting.lua` to additionally invoke the real action source against both disposable servers, substituting only scratch executable/config/state destinations. Every server and fixture is private and removed afterwards. Tests run on Linux API13 and Mac API13. A separate cross-machine acceptance uses private sockets on hive and M5; a real app key press remains operator QA.

Sources: existing `rexconfig/rex/waiting.lua` read 2026-11-13; Rex Lua API and CLI `rex do --help`, acquired 2026-11-13, expose `rex.server(label)` and `rex.servers()`. The runtime scan reports their actual types in `sources`.

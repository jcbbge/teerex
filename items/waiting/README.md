# Cross-host waiting navigation

`teerex waiting list|next|back|put-away [--config /ABS/hosts.json] [--hosts hive,m5] [--focus]`

The default config is `~/.config/teerex/hosts.json`; omitted `--hosts` scans **every** configured host. Transport uses the existing explicit named-host configuration, including its SSH identity and known-host checks. Each host is queried through one foreground Rex Lua connection, with autostart disabled. Only placed and detached agent panes registered in that host's `HOME/.local/state/teerex-agents` participate; the exact socket/session/block must match a tracked, unretired launch. The seat (label, registered agent name or board seat target), board, scratchpad viewers, receipt panes and unregistered fixtures are excluded. Registry evidence is read on the selected host; malformed or unreadable records fail the host scan closed. For each pane, the most urgent OSC 7501 record wins: blocked, error, done; equal urgency sorts oldest first, preserving nanoseconds. Working and idle records do not qualify. A failed host is reported in `sources`, sets `complete:false`, exits 1 and prevents focus; missing evidence never becomes zero waiting.

`list` returns unvisited waiting panes without moving focus. `next --focus` focuses the first pane on its owning server, bringing a detached pane into the right third beside that session's active pane first. Without `--focus`, `next` previews the winner without marking it visited. Focus changes server layout state; it does not establish that an app switched hosts or sessions. No client action is guessed or queued. `back --focus` returns to the previous registered agent context, including across hosts; stale history cannot offer an unregistered pane or a protected seat. Visited timestamps and the return trail live in `~/.local/state/teerex-waiting/navigation.json`; `--state /ABS` selects isolated state. A lock serializes overlapping presses. Only a successfully focused winner is marked visited; a new status timestamp qualifies again. The host name forms part of every visited key.

Supply `--here-host NAME --here-session session:UUID --here-block block:UUID` for exclusion and return navigation. `--here-server LABEL` resolves a Rex action's context label against configured names, host ids and SSH addresses. An unfamiliar label is resolved by finding the exact live session/block across all hosts; missing or ambiguous ownership is an error, never permission to act on the local host. `put-away` requires this exact context and detaches its pane on that host, refusing `seat` and a tab's last placed pane.

Rexconfig's `next_waiting` delegates cmd+j and triage j/k here. `put_away` delegates triage d. A missing teerex executable alone permits the prior local Lua implementation. A present executable with a missing verb, bad configuration or failed host reports failure. The Lua remains in the rexconfig repository; it is not installed by teerex.

Test: `TEEREX_BIN=/ABS/teerex REX_BIN=/ABS/rex python3 items/waiting/test_waiting.py -v`. Set `WAITING_LUA=/ABS/rexconfig/rex/waiting.lua` to additionally invoke the real action source against both disposable servers, substituting only scratch executable/config/state destinations. Every server and fixture is private and removed afterwards. Tests run on Linux API13 and Mac API13. A separate cross-machine acceptance uses private sockets on hive and M5; a real app key press remains operator QA.

Sources: existing `rexconfig/rex/waiting.lua` read 2026-11-13; Rex Lua API and CLI `rex do --help`, acquired 2026-11-13, expose `rex.server(label)` and `rex.servers()`. The runtime scan reports their actual types in `sources`.

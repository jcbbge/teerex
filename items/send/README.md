# send

[Operator/agent addendum: Who, What, When, Where, Why, How](../../docs/concierge/features.md#8-send-one-whole-message-paste-then-enter) covers current alpha.5 use, platform/API support, verification, privacy and recovery. [Current setup](../../docs/concierge/setup.md) installs alpha.5; the [standalone send cartridge](../../docs/cartridges.md) keeps native message transport, while combined-CLI [registered-seat routing](../boards/README.md) adds explicit inbox append before paste. Separate paste/Enter ACKs are not atomic delivery or consumption; no blind resend is safe.

**Experimental terminal-input module, not a global messaging authority.** `rex_send.run(allocator, args) !u8` uses the shared `supervised_child` ABI and is integrated into the combined CLI and native cartridge builds. Combined root routing is a separate boards-store operation; the standalone payload does not acquire that Python-backed routing surface. Installation does not change Rex configuration, agent-core files or running personal servers. Historical compatibility-only alpha.2 did not include send.

## Cooperative human hold and placeholders

The [clutch](../clutch/README.md) applies to every native send, including `--draft ignore`: `teerex clutch take|release|status --socket ABS --session ID --pane ID`. A held pane waits within `--draft-wait-ms`, then refuses `pane_held_by_human` without typing. Its receipt is retry-safe only before any message paste or draft-clear attempt. This binds cooperating teerex callers, not raw Rex writers or in-flight server calls; it is not a server input lease. Send only reads clutch state and never creates its directory or records; an absent record is released. Release deletes records; `teerex clutch prune [--apply]` plans/applies cleanup of old released records with absent targets. Private state uses `TEEREX_CLUTCH_DIR` or `~/.local/state/teerex/clutch` on the command/Rex host. Unreadable/unavailable/corrupt clutch state is reported as `clutch.state:"unknown"` with a named `clutch.failure_reason` and does not block send; only a confirmed hold blocks input. Default overall timeout is now draft wait+10000ms in both draft modes. Native cartridge sends share the same check.

The prompt parser recognizes `>`, `❯` and Codex's `›`. It ignores dim/grey suggestion segments while preserving real typed text, even text matching a placeholder verbatim. Extended SGR background/underline colour channels are skipped as complete parameters, so an RGB mode/channel value2 cannot accidentally toggle dim. The Codex fixture reproduces the observed `SGR1`, `48;2;41;44;49`, reset, then `SGR2` placeholder sequence acquired read-only from the reported pane on2026-11-13; no input was sent there. Pi-style split dim/fake-cursor segments use the same suggestion filter. This remains a screen heuristic, not an application draft API.

## Invoke and select deliberately

For a development build, use Zig **0.15.2** and `zig build -Doptimize=ReleaseSmall`; released installation needs no compiler. Native invocation:

```sh
teerex send --socket /absolute/path/to/existing/rex.sock \
  --session session:01234567-89ab-cdef-0123-456789abcdef \
  --block block:fedcba98-7654-3210-fedc-ba9876543210 \
  --from worker --message-file /absolute/path/to/message.txt \
  --draft guard --draft-wait-ms 30000
```

An absolute Unix socket, canonical lowercase full session/block IDs, a label, and either an absolute regular message file or `--message-file -` are required. The file/stdin is read once, without trimming or shell joining. Stdin must reach EOF within the overall deadline; interrupted/deadline input sends nothing. Its 1–65536 bytes must be valid UTF-8; ASCII controls other than LF/tab, including CR, ESC, NUL and DEL, are refused. The label is 1–128 UTF-8 bytes with no ASCII controls. Those checks are **not** a proof that the text is safe for the recipient. The exact paste text is `FROM <label>: <file bytes>`. One Enter key event follows on the same attached Rex connection.

**Choose a dedicated agent terminal that you are authorized to type into.** The selected session must contain the block as a visible terminal at validation time; detached and nonterminal blocks are refused. Draft guarding is now **on by default** (source follow-on #4). No active-pane/focus resolution, new terminal, server autostart, shell execution, chunk fallback, or retry is performed. `--draft ignore` explicitly restores the old paste/Enter behavior, including submission of existing pending input together with the message. A caller-selected agent terminal does not prove prompt/input safety. A terminal without bracketed-paste handling may treat embedded newlines as input submissions. Even a bracketed-paste-aware application may interpret or execute the message. Target validation is a prior read, not a conditional write or lease.

The separately installed `rex` CLI is resolved through PATH. `REX_SERVER`, `REX_SESSION`, `REX_BLOCK`, and `REX_CLIENT` hints are removed; explicit addresses select the connection. A forwarded socket still uses the CLI machine's filesystem, lock directory and inbox markers. It does not share locks with senders on the server host. No SSH/inbox forwarding or physical-host authentication is added.

## Existing agent-core contract and intentional differences

The actual source inspected was [`agent-send`](https://github.com/jcbbge/agent-core-public/blob/80c13e4c8d58a851fcab1085437d51f10080c831/primitives/tools/agent-messaging/agent-send) at commit `80c13e4c8d58a851fcab1085437d51f10080c831`. Its terminal branch acquires `${TMPDIR:-/tmp}/agent-send.${blockUUID}.lock` using mkdir, pastes `FROM <from>: <message>`, then presses Enter. Its other behavior includes inbox routing, input-clearing, heuristic draft restoration, and a numbered-chunk fallback. The source was read and exercised, not copied into teerex or modified.

teerex uses that **same mkdir/rmdir lock name** and exact envelope. Its default draft guard now ports the reference prompt/colour parser and clears/restores detected input within the same attached Rex connection. It never falls back after a failed/uncertain paste, because the paste may already have taken effect. The file interface avoids Bash `$*` joining and preserves trailing newlines. The current bridge's inbox routing remains separate: teerex refuses a local `${AGENT_INBOX_DIR:-$HOME/.local/state/agent-inbox}/${blockUUID}.inbox` marker, including a marker naming a remote host. It checks before acquisition, during waits and after acquisition. Creation/removal of markers by noncooperating processes can still race these checks. Empty environment values use the same Bash `:-` defaults. Unknown lookup permissions fail closed.

**Only cooperating processes on the same host and effective temp directory serialize.** The lock covers the entire teerex Rex invocation and child cleanup, not just paste. Two sockets using the same block UUID conservatively contend. Different temp directories, hosts/users with different namespaces, direct Rex clients, humans, and clients ignoring the lock bypass it. A direct Rex write succeeded while this lock was held in validation. Native Rex block ownership is not an exclusive input lease; it is not used as one. There is no server-enforced atomic paste-plus-Enter operation, no conditional observation token, and no promise of atomic delivery across arbitrary clients.

The default overall monotonic deadline is **draft wait + 10000 ms** (**40000 ms** by default in both draft modes), range **100–115000**. It includes input reading, lock wait, startup and RPC work; polling waits at most 20 ms between attempts. The remaining budget supervises the Rex child. Shared process-group cancellation/cleanup can add bounded drain/escalation time, and filesystem/kernel operations, scheduling and final stdout backpressure are not hard real-time bounded. SIGINT/TERM request cancellation. SIGKILL/crash can strand a lock or leave uncertain terminal effects; no stale-lock stealing is implemented. Remove a stranded lock only after checking that its sender is gone and deciding how to handle possible prior input. A shared, attacker-controlled TMPDIR is not a security boundary.

## Default draft guard (`--draft guard|ignore`)

`--draft guard` is the default for native send and internal agent notifications/briefs. Within the same Rex connection it reads the target's VT capture, considers the last 15 nonempty lines and recognizes `>`/`❯`/`›` prompts with optional `│`/`┃`/`|` borders. Like agent-core's `GUARD_PY`, it removes dim SGR2, grey SGR90, indexed240–250 and equal RGB components below160. It also recognizes indexed8 because the tested Rex VT renderer normalizes SGR90 into `38;5;8`. Cursor-forward CSI `nC` becomes `n` spaces (default1), in the current style, so internal single/double spaces survive while grey/dim suggestion spaces remain ignored. Other CSI codes are stripped. NBSP after the prompt marker is treated as separator whitespace. Whitespace is trimmed by the reference heuristic; **Claude Code does not render trailing spaces, so they cannot be restored**. Wrapped/multiline/editor-specific input is not reconstructed.

When a draft exists, poll every approximately250ms until it is empty or unchanged for1500ms. `--draft-wait-ms N` defaults30000, range0–55000. The bound ends the wait even during ongoing typing (`bound_reached:true`); the latest parsed draft is saved. Before clearing, both message and restore paste must fit the existing encoded RPC bound. Ctrl-U clears detected input; after a short settling read it is tried at most once more. A still-nonempty draft refuses as `draft_not_cleared`, before message paste. Empty prompts and grey suggestions incur no quiet-window wait or clear event.

Paste and Enter retain the existing ordered, separate ACKs. After Enter ACK, wait400ms, paste the saved draft **without Enter**, then poll its capture approximately every100ms for up to1500ms, stopping as soon as it matches. Delayed terminal redraws can therefore verify without another paste. A failed or still-unverified restore **does not change the acknowledged send**: outcome remains `events_acknowledged`, exit0, `failure_reason:null`, with `draft.restored:false`, `draft.restore_verified:false` and top-level `draft_warning:"draft_restore_failed"` or `"draft_restore_unverified"`. A verified restore has `draft_warning:null`. No restore paste or message is retried. `--draft ignore` bypasses detection, clearing, waiting and restoration and gives the old behavior explicitly.

The receipt adds `draft:{mode,detected,chars,waited_ms,bound_reached,cleared,restored,restore_verified}`. `chars` counts Unicode code points in the saved parsed draft; `waited_ms` uses the controller's monotonic timer. Clear/restore verification fields are null when not attempted. **Draft text is never emitted in frames, receipts, logs or errors.** Guard-mode raw backend diagnostics are suppressed because an RPC error could include captured/restored typing. Fixed failure names and acknowledged stages remain visible.

This is a heuristic, not an input lease: **keystrokes in the few milliseconds between the final read and Ctrl-U can land in the cleared line**, and typing during message/restore events can still race them. Cancellation, deadline or transport failure after clearing can interrupt restoration. Prompt detection, paste/Enter and restore are separate calls and do not establish arbitrary application safety. Check the receipt; never resend automatically.

Managed-agent send subprocess budgets now cover the native115000ms maximum plus cleanup (120s); hook/callback/channel response wrappers allow250s for two fixed destinations. Named-host routing does not add a shorter send timeout. Registered-seat boards routing accepts these flags but appends to the inbox without terminal input; it uses the same default overall input budget and115000ms maximum. The lock, encoding rules and no-retry policy remain unchanged.

## Encoded bounds, not just raw-message size

Rex preview.16 caps control messages at **65536 bytes**. A 65536-byte message plus escaped JSON cannot fit. Before spawning Rex, teerex rejects a minimal JSON object containing only the paste text over **60000 bytes**, which also avoids Linux's per-argument exec limit for LF-heavy input. Controller-only clutch metadata does not reduce the paste budget. Before paste, fixed Lua uses **Rex's own JSON encoder** to size a conservative JSON-RPC-shaped envelope containing the exact session/block IDs and paste event. Values over **60000** are refused; more than 5 KiB remains for protocol framing/request-ID differences. `encoded_rpc_bytes` is that preflight encoding size, **not a wire capture**; it is null if Zig rejected before Rex ran. `encoded_argument_bytes` separately records the outer arguments size. No message is truncated or split.

With label `worker` and canonical IDs, the measured preflight overhead is 234 bytes. Boundary tests accepted 59766 printable ASCII bytes, 29883 α characters (59766 raw UTF-8 bytes), 29883 LF characters, 29883 quotes, and 9961 `<` characters, each at exactly **60000 encoded bytes**. One more ASCII byte was refused at **60001**, before paste. Full raw 65536-byte printable, Unicode and LF-heavy files were explicitly rejected before paste. Limits change with the label and escaping; these are synthetic test sizes, not universal raw payload allowances.

## Receipt and unknowns

Normal controller outcomes emit one `schema_version=1`, `kind="send_result"` JSON object. Usage failures exit 2 without JSON. Input-file/OS/allocation/output failures can exit 1 without a complete receipt. Always inspect exit status and parse the whole packet; never automatically retry a missing or unsuccessful receipt.

- `events_acknowledged` / exit **0**: both paste and Enter were acknowledged and the Rex invocation completed successfully. **Not “delivered,” consumed, safe, or task-complete.** On one Rex connection the calls are ordered; acknowledgement may precede completion of event effects.
- `refused`, `inbox_refused` / exit **1**: encoded-size, revision/target or local inbox refusal. `failure_reason` and the reported source revision identify the refusal where available. API10–13 is the accepted integer range; revision 11 has not been exercised here. A numeric range alone does not establish every server's capability.
- `uncertain`, `backend_error` / exit **1**: command/transport/framing failed. Input effects may have occurred, including when no attempt frame reached the controller. Backend diagnostics are bounded by the shared supervisor and printed on stderr only in ignore mode. A paste ACK followed by failed/missing Enter remains `paste.acknowledged=true`, `enter.acknowledged=false`; no invented success or retry follows.
- `deadline_exceeded` / exit **124**, `cancel_requested` / exit **130/143**: work stopped by deadline/SIGINT/SIGTERM. Already reported attempts/ACKs remain in the packet; stopping the CLI does not retract queued input or prove recipient cancellation.

`paste.attempted` / `enter.attempted` mean **received local pre-call frames**, not verified server dispatch. False means “not reported,” not always “definitely never attempted.” `backend_invoked=false` means the Rex invocation was not made; true is not proof it connected. Source can be null. `cooperative_lock.acquired` reports actual local acquisition. Lock cleanup failures are non-successful even if both ACKs were seen. `server_enforced_atomic_delivery=false`, `exclusive_input_lease=false`, `application_consumption="not_assessed"`, `prompt_safety="not_assessed"`, and `retry_safe=false` remain explicit.

Message contents are omitted from the receipt, but the Rex JSON arguments can appear in process listings or diagnostics. Paths, labels, messages and returned diagnostics may contain private data; the guard suppresses raw backend diagnostics to protect drafts; ignore-mode diagnostics are not redacted. Use only trusted binaries and review evidence before sharing it.

Terminal deliveries into the native server-wide `seat` label (block or window) publish a child OSC7501 record `msg/<sender>` with `FROM <sender>` and the first 180 Unicode characters of the first message line, controls removed. Unsafe key bytes are percent-encoded. Root records remain untouched. Optional `--status-id`, `--status-state done|blocked|clear`, and `--status-message` customize that record. The host-local tty is opened write-only, nonblocking and without acquiring a controlling tty; a single write emits each report. The optional Python helper has a 250ms post-delivery budget. Failure never changes acknowledged delivery; `status_record` reports written, not_requested, tty_unavailable, failed, short_write or deadline_exceeded. Named-host execution performs this on the selected pane host. Legacy explicit inbox routing remains unchanged.

Successful terminal send also restores OSC111 when it finds the supervised `teerex/tint` child record. Profiles with tint disabled use a different child ID and receive no colour write. The same `status_record` receipt reports the best-effort write outcome.

On API13, an explicitly targeted detached terminal is validated against
`session.list_blocks` when absent from the window view. The same clutch, draft
capture/clear/restore and paste/Enter checks apply; sending does not place or focus
it. Earlier APIs retain their placed-terminal check.

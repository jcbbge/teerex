# Cooperative human clutch

`teerex clutch take|release|status --socket ABS --session session:UUID --pane block:UUID [--reason TEXT]` records whether the human holds a pane. `take` and `release` are idempotent: receipts include `held`, `changed`, and state path. Repeating `take` preserves its timestamp/reason. `release` deletes the hold record and returns `record:null`, then drains the queue; repeating it drains only remaining pending records. `status` reads saved state; it does not claim the pane exists or the server is reachable. No expiry or automatic hand-back runs.

The clutch binds **teerex callers only**. It does not stop raw `rex` writers, Rex.app keys or other programs. It is not an input lease. A hold observed by send prevents its subsequent input; there remains a race between the final local check and a server call, and in-flight input cannot be revoked. Server-enforced exclusion and human key revocation are upstream requests **R1/R4**. Do not describe this cooperative control as instantaneous cancellation of already dispatched input.

## Send behavior

All native sends check the clutch. Default sends into held panes or guarded panes with present or unknown input create private pending records and return `outcome:"queued"`. No input events are sent. A new send joins existing pending records in ID order. A later guarded send attempts to drain them before dispatching its own message.

`send --no-queue` waits up to `--draft-wait-ms` for an empty, released pane. The receipt includes the refusal reason and whether retry is safe. A paste attempt makes an uncertain delivery ineligible for automatic replay.

## Private state and scope

State lives under `TEEREX_CLUTCH_DIR`, or `~/.local/state/teerex/clutch`. The directory must be owned exact0700, its lock and JSON files owned single-link regular0600; final symlinks are refused. Take, release and the first queued send create the private leaf if missing; parents are trusted operator filesystem context. The state key hashes the canonical socket path, session and full pane ID. Socket aliases of an existing server therefore share a hold; a new pane ID or another server path does not inherit one. Status only reads. Ordinary unheld sends create no clutch state; deferred sends create private queue records. Missing state is released, with the same path rechecked before each input.

Atomic writes and a short mutation-only flock protect take/release. The clutch mutation lock never spans draft waits or message delivery; a separate per-queue drain lock serializes release delivery. take/release lock contention waits at most1s. Take/release/status refuse corrupt or unsafe state with a named `failure_reason`; ordinary send reports `clutch.state:"unknown"` with that reason and proceeds without a hold. Only a positively read hold blocks input. Commands and the Rex server must run on the same machine with the same state path. The default socket comes from `REX_SERVER` or the local runtime path. An inaccessible/corrupt state file during send reports `unknown` and proceeds; it never turns a clutch-store fault into a messaging outage. Keep the directory until all send callers stop using it; do not delete it to clear a hold. Deliberately `release` instead.

## Durable held deliveries

`clutch queue --socket ABS --session ID --pane ID --json` inspects the durable queue without changing it. Messages have ordered IDs, pending/inflight state, sender, age and first line; `--show` includes full bodies. Queue directories are owned0700 and records owned single-link0600, with symlinks refused. There is no entry-count or queue-size cap. Complete records are flushed and atomically renamed; acknowledged records are removed.

Release deletes the hold, then drains. `clutch drain --socket ABS --session ID --pane ID [--json]` uses the same guarded delivery and preserves the hold. When the pane is held or contains present or unknown input, draining stops with the record pending. An empty queue returns a no-op receipt. A budgeted Stop drain leaves records pending when it lacks time to verify a paste. A record is durably claimed before dispatch. An uncertain dispatch stays inflight and stops the current drain. Later drains skip inflight IDs and deliver pending records when input is empty. Send and drain receipts include `queue_uncertain`, the count of inflight records for the pane. Drain receipts also list uncertain IDs, and queue inspection marks them with `delivery: "uncertain"`. Use `clutch queue --resolve ID` with the same target flags to remove an inflight record explicitly. Resolution removes the record without sending any input. No background drain or automatic retry runs.
